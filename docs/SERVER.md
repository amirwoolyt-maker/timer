# تست و میزبانی نسخهٔ وب راهیار

نسخهٔ فعلی برنامه `1.0.0` است. وب و اندروید از یک سورس Flutter ساخته می‌شوند.

## ساخت و تست محلی

Flutter `3.50.1` را نصب کنید و در پوشهٔ پروژه اجرا کنید:

```sh
flutter pub get
flutter build web --release --no-web-resources-cdn
python scripts/serve_web.py --port 8080
```

تست خودکار هدرها، مسیرهای برنامه، پاسخ خطای فایل‌های ناموجود و نوع فایل WASM:

```sh
python -m unittest discover -s scripts -p "test_*.py"
```

صفحهٔ `http://localhost:8080` را باز کنید. گزینهٔ `--no-web-resources-cdn` منابع موتور نمایش را کنار برنامه قرار می‌دهد تا اجرای رابط به دریافت فایل از CDN وابسته نباشد.

برای تست از دستگاه دیگری در همان شبکه:

```sh
python scripts/serve_web.py --bind 0.0.0.0 --port 8080
```

سرور پایتون صرفاً برای پیش‌نمایش است. در محیط عمومی از Docker یا Caddy استفاده کنید. روی گوشی و آدرس عمومی، HTTPS برای قابلیت‌های مرورگر مانند ذخیره‌سازی امن و مجوزها لازم است؛ `localhost` استثنای تست محلی است.

## سرور با Docker

این روش فقط به Docker نیاز دارد و Flutter را داخل مرحلهٔ ساخت نصب می‌کند. کلید امضای اندروید و رمزها وارد تصویر نمی‌شوند.

```sh
docker build -t rahyar:1.0.0 .
docker run -d --name rahyar --restart unless-stopped -p 8080:8080 rahyar:1.0.0
```

خروجی روی پورت `8080` است و مسیر `/healthz` باید `ok` برگرداند. برای دامنهٔ عمومی، پراکسی HTTPS را جلوی پورت `8080` قرار دهید. هدرهای زیر نباید توسط پراکسی حذف شوند:

```text
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
Cross-Origin-Resource-Policy: same-origin
```

## سرور بدون Docker

بعد از ساخت، کل پوشهٔ `build/web` را همراه `Caddyfile` روی سرور کپی کنید. در پوشهٔ پروژه اجرا کنید:

```sh
caddy run --config Caddyfile
```

پورت پیش‌فرض `8080` است. برای دامنه و HTTPS خودکار در لینوکس:

```sh
APP_ADDRESS=planner.example.com APP_ROOT=/srv/rahyar caddy run --config Caddyfile
```

در این مثال محتوای `build/web` باید در `/srv/rahyar` قرار گرفته باشد و DNS دامنه به سرور اشاره کند. برای HTTPS، پورت‌های `80` و `443` باید در دسترس Caddy باشند.

اگر خروجی آمادهٔ وب را از GitHub Release گرفتید، فایل فشرده را باز کنید و پوشهٔ شامل `index.html` را به‌عنوان ریشهٔ سایت قرار دهید. فقط فایل HTML کافی نیست؛ پوشه‌های `assets`، `canvaskit` و فایل‌های `sqlite3.wasm` و `drift_worker.js` نیز لازم‌اند.

## محدودهٔ داده و تست

اطلاعات شخصی برنامه در SQLite همان دستگاه یا همان مرورگر ذخیره می‌شود. میزبانی وب، داده‌های مرورگرهای مختلف را با یکدیگر همگام نمی‌کند. تغییر دامنه، پورت، مرورگر یا پاک‌کردن دادهٔ سایت فضای ذخیره‌سازی جداگانه‌ای ایجاد می‌کند. از پاک‌کردن دادهٔ سایت برای رفع خطا استفاده نکنید مگر اینکه نسخهٔ پشتیبان لازم را داشته باشید.

سورس اولیهٔ React نیز حساب‌ها، چت و اتاق‌ها را در `localStorage` نگه می‌داشت و API عملیاتی برای کاربران واقعی نداشت. سرور استاتیک جای سرویس احراز هویت، پیام‌رسانی هم‌زمان، رتبه‌بندی چندکاربره یا پشتیبان‌گیری شبکه‌ای را نمی‌گیرد. اتصال این قابلیت‌ها به کاربران دستگاه‌های دیگر به طراحی و استقرار یک بک‌اند جداگانه نیاز دارد؛ این راهنما ادعای اتصال چندکاربره ندارد.

برای تست انتشار، صفحه را باز کنید، یک کار و یادداشت بسازید، صفحه را تازه‌سازی کنید و باقی‌ماندن داده را بررسی کنید. سپس تایمر و همهٔ گزینه‌های بخش «بیشتر» را روی صفحهٔ باریک موبایل و صفحهٔ دسکتاپ بررسی کنید. `/sqlite3.wasm` باید با نوع `application/wasm`، فایل ناموجود مانند `/missing.js` با وضعیت `404` و مسیر برنامه مانند `/tasks` با صفحهٔ اصلی پاسخ داده شود.
