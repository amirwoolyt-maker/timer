# راهیار

نسخهٔ Flutter اپلیکیشن برنامه‌ریزی درس و زندگی روزانه با رابط فارسی راست‌چین و تم «Cosmic Emerald». شمارهٔ نسخه و ساخت طبق سیاست پروژه فعلاً `1.0.0+1` باقی می‌ماند.

## اجرا

ورود آنلاین با کد ایمیلی Appwrite و اتصال پست‌ها، پاسخ‌ها، پسندها، گروه‌ها و اتاق‌ها پیاده شده است. فعال‌شدن واقعی آن به ساخت schema و تنظیم platform در پروژهٔ Appwrite نیاز دارد؛ مراحل در [راهنمای آنلاین](docs/ONLINE_SETUP.md) آمده‌اند. شناسهٔ پروژه و endpoint در `config/appwrite.json` عمومی هستند؛ هیچ کلید مدیریتی در برنامه قرار نمی‌گیرد. برای اجرای debug متصل به این پروژه:

```bash
flutter run -d chrome --dart-define-from-file=config/appwrite.json
```

اجرای بدون این فایل، حالت محلی قبلی را نگه می‌دارد. ابزارهای شخصی آفلاین‌اند؛ اتصال حساب به‌معنی همگام‌سازی کارها و یادداشت‌ها نیست. ساخت APK و بسته‌های وب انتشار همچنان فقط در GitHub Actions انجام می‌شود.

```bash
flutter pub get
dart run build_runner build
flutter run -d chrome
```

برای خروجی وب:

```bash
flutter build web --release --no-web-resources-cdn
python scripts/serve_web.py --port 8080
```

## امضای نسخهٔ اندروید

برای نصب روی نسخهٔ قبلی، شناسهٔ برنامه (`ir.studypath.rahyar`) و کلید امضای انتشار باید ثابت بمانند. افزایش نسخه یا شمارهٔ ساخت فقط با درخواست صریح کاربر انجام می‌شود؛ اصلاح فعلی همان `1.0.0+1` را نگه می‌دارد. فایل کلید و `android/key.properties` محرمانه‌اند؛ آن‌ها را در گیت یا مخزن عمومی قرار ندهید و از هر دو نسخهٔ پشتیبان امن تهیه کنید.

مسیر اصلی ساخت نسخهٔ انتشار، GitHub Actions است؛ نیازی به نصب Android SDK روی رایانهٔ کاربر نیست. دستور زیر فقط در صورت درخواست صریح ساخت محلی استفاده می‌شود:

```bash
flutter build apk --release
```

برای ساخت روی دستگاه دیگری، همان فایل کلید را امن منتقل کرده و `android/key.properties` را با این قالب بسازید (`storeFile` نسبت به پوشهٔ `android` است):

```properties
storePassword=YOUR_STORE_PASSWORD
keyPassword=YOUR_KEY_PASSWORD
keyAlias=rahyar-upload
storeFile=app/rahyar-upload-key.jks
```

برای ساخت خودکار فایل نصب در GitHub، فایل کلید را به صورت Base64 در Secret مخزن با نام `ANDROID_KEYSTORE_BASE64` قرار دهید و رمزها و نام مستعار را به ترتیب در Secrets با نام‌های `ANDROID_KEYSTORE_PASSWORD`، `ANDROID_KEY_PASSWORD` و `ANDROID_KEY_ALIAS` ذخیره کنید. اجرای دستی Workflow با نام `Test and release` و ورودی `v1.0.0`، پس از تحلیل و تست، APK امضاشده و ZIP وب را در همان Release منتشر می‌کند. ارسال معمولی تغییرات به `main` فقط تست و ساخت وب را اجرا می‌کند؛ اگر پیام کامیت شامل `[release]` باشد، ساخت APK و انتشار نیز روی GitHub Actions اجرا می‌شود. برچسب انتشار همیشه از نسخهٔ `pubspec.yaml` گرفته می‌شود. بدون درخواست تغییر نسخه، برچسب بالاتری نسازید. این Secrets را در فایل‌های مخزن ننویسید.

پایگاه‌دادهٔ Drift روی موبایل از SQLite بومی و روی وب از `sqlite3.wasm` و `drift_worker.js` استفاده می‌کند. وب باید با هدرهای زیر سرو شود تا ذخیره‌سازی اشتراکی WASM فعال بماند:

```text
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

فایل `Caddyfile` نمونهٔ میزبانی خروجی `build/web` را دارد. دستورهای استقرار با Docker، دامنه و HTTPS در [راهنمای سرور](docs/SERVER.md) آمده‌اند. بستهٔ وب، موتور نمایش و فونت‌ها را همراه خود دارد و برای دریافت آن‌ها به CDN وابسته نیست.

## ساختار

- `lib/core`: تم، وضعیت زبان/ظاهر و قالب‌بندی تاریخ و اعداد
- `lib/data`: جداول Drift، مهاجرت پایگاه‌داده و Providerهای Riverpod
- `lib/features`: صفحه‌های کارها، یادداشت‌ها، تایمر، همراهان و گرید ابزارهای بیشتر
- `assets/fonts`: وزن‌های فونت Vazirmatn

## قابلیت‌های پیاده‌سازی‌شده

کارها با افزودن و ویرایش، اولویت، دسته، برچسب، تاریخ شمسی، ساعت، تکرار، تکمیل و جستجو؛ یادداشت‌های آفلاین با سقف ۱۵ مورد و سنجاق‌کردن؛ تایمر پومودورو با تنظیم زمان کار و استراحت، تایمر درس و کرنومتر با بازیابی جلسه؛ تقویم جلالی؛ پروژه‌ها؛ داشبورد آمار و عادت‌ها؛ ۱۶ ابزار بخش بیشتر؛ حالت تمرکز با تأیید خروج؛ سطل زباله با بازیابی و حذف دائمی؛ پروفایل و کتاب‌های شخصی؛ منابع و فهرست دانشگاه‌ها؛ اجتماع، پیام‌ها و اتاق‌های محلی؛ چرخه؛ یادآور مکان؛ و حداکثر پنج آلارم با سطح چالش متناسب با مقطع و قفل موقت پس از شش پاسخ نادرست.

Android دارای پل بومی زمان‌بندی آلارم و یادآوری کارها، پخش صدای زنگ، انتخاب فایل صوتی و بازیابی زمان‌بندی پس از راه‌اندازی دستگاه است؛ این قابلیت‌ها به مجوزهای سیستم وابسته‌اند و باید روی گوشی واقعی هم آزموده شوند. وب و iOS سرویس بومی زنگ پس‌زمینه ندارند. یادآور مکان در زمان بازبودن صفحه و با مجوز کاربر بررسی می‌شود. تنظیم بی‌صدایی حالت تمرکز در Android نیز به مجوز سیستم وابسته است.

اطلاعات شخصی روی همان دستگاه یا مرورگر ذخیره می‌شود. وقتی تنظیمات Appwrite در ساخت فعال باشد، اجتماع، چت گروهی، اتاق‌ها و انتشار اختیاری زمان مطالعه از سرور مشترک استفاده می‌کنند و ورود ایمیلی لازم دارند. بدون تنظیمات، مسیرهای محلی قبلی باقی می‌مانند. اتاق‌های آنلاین عمومی برای کاربران واردشده‌اند؛ عضویت به‌معنی حضور لحظه‌ای نیست و زمان‌های منتشرشده خوداظهاری‌اند. ارسال رسانه، پیام خصوصی، مدیریت محتوا و همگام‌سازی اطلاعات خصوصی هنوز پیاده نشده‌اند. میزبانی وب به‌تنهایی پایگاه‌داده و حساب آنلاین ایجاد نمی‌کند.

ساخت محلی Android به Android SDK و Java نیاز دارد؛ مسیر انتشار امضاشده در GitHub Actions تنظیم شده است. ساخت iOS باید روی macOS انجام شود. موفقیت تست‌های Flutter یا ساخت وب به معنی تأیید اجرای بومی آلارم روی گوشی نیست.
