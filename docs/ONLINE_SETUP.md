# راه‌اندازی آنلاین آزمایشی راهیار

نسخه همچنان `1.0.0+1` است. مسیر آنلاین از Appwrite Cloud و کد ورود ایمیلی استفاده می‌کند.

## تنظیم عمومی پروژه

فایل `config/appwrite.json` شامل شناسهٔ عمومی `123` و نشانی پایهٔ `https://fra.cloud.appwrite.io/v1` است که صاحب پروژه داده است؛ ساخت schema با این شناسه روی سرور موفق بوده است. برای پروژهٔ دیگری این مقادیر باید تغییر کنند. نشانی SDK نباید به `/account` ختم شود. این فایل فقط تنظیم عمومی است؛ **هیچ API key، رمز، OTP یا session نباید وارد آن شود**.

در Appwrite Console، پروژهٔ خود را انتخاب کنید:

1. یک Platform اندروید با package `ir.studypath.rahyar` ثبت کنید.
2. یک Platform وب با hostname دامنهٔ سایت نهایی و برای آزمایش `localhost` ثبت کنید. ثبت آدرس سایت کامل به جای hostname درست نیست.
3. در Auth، روش Email OTP باید فعال باشد. ورود برنامه رمز عبور ندارد؛ اولین تأیید ایمیل حساب را می‌سازد و دفعات بعد وارد همان حساب می‌شود.
4. از سرویس ایمیل پیش‌فرض Cloud برای تست استفاده کنید؛ اعتبار و محدودیت ارسال را در پنل خودتان بررسی کنید. ایمیل‌ها در Free قالب عمومی Appwrite دارند؛ SMTP شخصی و قالب اختصاصی در Cloud به طرح پولی وابسته است و برای این آزمایش لازم نیست.

## ساخت جدول‌ها؛ فقط یک بار

در ۲۶ نوامبر ۲۰۲۶، پایگاه‌دادهٔ `rahyar` و هر هفت جدول با کلید موقتِ ارائه‌شده توسط صاحب پروژه روی سرور ساخته شدند. دستور زیر برای بازسازی یا پروژهٔ دیگر است؛ اسکریپت با اجرای دوباره داده‌های موجود را پاک نمی‌کند. کلید در برنامه و فایل‌ها ذخیره نشده است. پس از پایان راه‌اندازی، کلید موقت باید از Console لغو شود.

یک server API key موقت برای همین پروژه بسازید؛ فقط دسترسی‌های خواندن و نوشتن Databases، Tables، Columns و Indexes را برای ساخت schema انتخاب کنید. کلید را در چت، کد، آرگومان خط فرمان یا گیت قرار ندهید.

در ترمینال پروژه اجرا کنید:

```powershell
python scripts/setup_appwrite.py
```

اسکریپت کلید را به‌صورت مخفی با `getpass` می‌گیرد، در حافظه مصرف می‌کند و ذخیره یا چاپ نمی‌کند. پس از موفقیت، کلید موقت را از Console حذف کنید. متغیر محلی `APPWRITE_ADMIN_KEY` هم برای اجرای غیرتعاملی پشتیبانی می‌شود، اما آن را در فایل نسخه‌گذاری‌شده ننویسید.

هفت جدول `posts`، `comments`، `likes`، `messages`، `rooms`، `members` و `scores` ساخته می‌شوند. ساخت رکورد فقط برای کاربران واردشده مجاز است. Row security فعال است؛ برنامه در هر رکورد، خواندن را به کاربران واردشده و ویرایش/حذف را به صاحب همان رکورد می‌دهد. هیچ مجوز خواندن عمومی برای مهمان‌ها و هیچ مجوز ویرایش عمومی روی جدول داده نمی‌شود. اسکریپت برای جدول موجود با مجوز ناسازگار متوقف می‌شود و دسترسی‌ها را بی‌خبر بازنویسی نمی‌کند.

رکوردهای این هفت جدول **فضای مشترک آزمایشی** هستند؛ اتاق‌ها خصوصی نیستند. نام نمایشی یکتا یا هویت تأییدشده نیست. زمان‌های مطالعه خوداظهاری‌اند. برای عرضهٔ عمومی به مدیریت محتوا، گزارش/مسدودسازی و اعتبارسنجی سمت سرور نیاز داریم.

## ساخت و میزبانی رایگان وب

ساخت release فقط در GitHub Actions انجام می‌شود. Workflow موجود حالا `config/appwrite.json` را برای APK و وب مصرف می‌کند و این دو بستهٔ وب را خروجی می‌دهد:

- `rahyar-web-1.0.0.zip`
- `rahyar-appwrite-site-1.0.0.tar.gz`

در نسخهٔ متصل، صفحهٔ ورود قبل از ابزارهای اصلی نمایش داده می‌شود. نشست معتبر قبلی نیاز به دریافت مجدد کد ندارد. پس از تأیید کد، فرم تکمیل نام، سن، پایه، جنسیت و آواتار برای حساب ناقص نمایش داده می‌شود و پس از ذخیره محیط اصلی باز می‌شود؛ همان فرم بعداً از حساب یا پروفایل قابل ویرایش است. ۱۲ آواتار تصویرسازی‌شده وجود دارد؛ آپلود عکس شخصی هنوز پیاده نشده است.

پروفایل در Account Preferences خصوصی Appwrite با کلید `rahyarProfile` ذخیره می‌شود و تنظیمات دیگر حساب حفظ می‌شوند. فقط نام نمایشی به پست/چت کپی می‌شود؛ سن، پایه، جنسیت، ایمیل و آواتار به جدول‌های عمومی ارسال نمی‌شوند. کش خصوصی هر حساب روی دستگاه با شناسهٔ همان حساب جدا می‌شود. کش SQLite رمزگذاری اضافه ندارد و ابزارهای شخصی محلی روی همین دستگاه مشترک باقی می‌مانند. هنگام قطع اینترنت، نشست کش‌شده امکان استفاده از ابزارهای آفلاین را می‌دهد؛ ویرایش حساب و فضای مشترک نیازمند اتصال واقعی‌اند. اگر بررسی حساب خطا بدهد و کشی نباشد، گزینهٔ ادامه با ابزارهای آفلاین نمایش داده می‌شود. آلارم در حال زنگ حتی در حالت خارج‌شده از حساب قابل حل است.

برای میزبانی روی همان Appwrite، در Sites یک سایت Static بسازید، در Deployments گزینهٔ Manual را انتخاب و فایل `tar.gz` ساخته‌شده در Actions را بارگذاری کنید. محتوای آن از قبل کامپایل شده است؛ نیازی به ساخت Flutter روی رایانه نیست. دامنهٔ نهایی را به Platform وب پروژه اضافه کنید. راهنمای رسمی: https://appwrite.io/docs/products/sites/deploy-manually

برای میزبانی استاتیک جایگزین، ZIP را می‌توان روی Cloudflare Pages بارگذاری کرد. فایل `_headers` نیز همراه وب قرار می‌گیرد تا سرویس‌هایی که آن را پشتیبانی می‌کنند هدرهای ذخیره‌سازی WASM را تنظیم کنند. هدرهای COOP/COEP و باقی‌ماندن داده بعد از refresh باید روی میزبان انتخابی آزمایش شوند.

برای اجرای **debug** محلی، نه ساخت release:

```powershell
flutter run -d chrome --dart-define-from-file=config/appwrite.json
```

## آزمون واقعی با دو حساب

1. با ایمیل اول کد بگیرید، عبارت امنیتی ایمیل و برنامه را تطبیق دهید و وارد شوید؛ نام، سن، پایه، جنسیت و آواتار را تکمیل و ذخیره کنید. ببینید فرم خودکار بسته می‌شود، سپس برنامه را دوباره باز کنید و حفظ پروفایل را بررسی کنید.
2. در یک مرورگر یا گوشی دیگر با ایمیل دوم وارد شوید.
3. یک پست، پاسخ، پسند و پیام گروهی بسازید؛ دیده‌شدن تغییر در دستگاه دوم را بررسی کنید.
4. اتاق بسازید، با حساب دوم عضو شوید و در گفت‌وگوی همان اتاق پیام بدهید. فهرست اعضا حضور لحظه‌ای محسوب نمی‌شود.
5. از حساب دوم تلاش کنید رکورد حساب اول را تغییر/حذف کنید؛ API باید دسترسی را رد کند. مخفی‌بودن دکمه به‌تنهایی آزمون امنیت نیست.
6. خروج از حساب و بازشدن دوبارهٔ برنامه را امتحان کنید. در حالت خارج‌شده امکان ارسال و خواندن فضای مشترک از برنامه وجود ندارد.
7. اطلاعات خصوصی SQLite خودکار ارسال نمی‌شوند. انتشار زمان مطالعه فقط با دکمهٔ صریح کاربر انجام می‌شود؛ همگام‌سازی کارها/یادداشت‌ها پیاده نشده است.

تست‌های خودکار ورود از backend بدل استفاده می‌کنند؛ موفقیت آن‌ها جای تحویل ایمیل واقعی، دسترسی‌های سرور و آزمون دو حساب واقعی را نمی‌گیرد.
